AIR-GAPPED DEFENSE ARCHITECTURE

Institutional Attack Surface Mitigation

POLICY: ZERO-KNOWLEDGE EXECUTION CORE
1. UNIDIRECTIONAL TELEMETRY MIRROR

The public web interfaces (e.g. ictflux.app) only read sanitized tick outputs from an egress-only read-only telemetry mirror. The actual order routing daemon runs on an air-gapped private VPS with zero public ingress ports.

2. HARD RISK CIRCUIT BREAKERS

Risk parameters (daily loss floor, consecutive loss halt, maximum position delta) are compiled directly into the binary. No remote client, API call, or web command has the permission to modify risk thresholds.

3. C FFI MEMORY POINTERS

Order dispatch avoids slow HTTP or JSON serialization. Python passes raw struct pointers directly to MetaTrader's C-runtime API via FFI, eliminating memory leaks and neutralizing MITM network injection vectors.

DEFENSE SPECIFICATION // ZERO COMPROMISE

How Every Connected System Is Hardened

Whether running God's Eye or a campus booking portal, all endpoints adhere to these sovereign security standards:

[ I. TIMING-SAFE HMAC ] SHA-256

All inbound payment webhooks (Paystack) and broker state signals are validated against constant-time HMAC SHA-256 signatures before processing. Replay attacks are neutralized via 60-second timestamp validation windows.

[ II. STRICT ROW-LOCK ISOLATION ] FOR UPDATE

Financial state changes in ChopOS, Ojaja Cinemas, and Luxe Booking execute within explicit PostgreSQL transactions using row-level locking (`SELECT ... FOR UPDATE`). No race condition can trigger an unbacked ticket or double disbursement.

[ III. AIR-GAPPED ORCHESTRATION ] EGRESS-ONLY

No live execution keys or private trade algorithms are exposed to browser clients. Frontends connect exclusively to stateless reverse-proxies serving pre-computed, sanitized data feeds.
